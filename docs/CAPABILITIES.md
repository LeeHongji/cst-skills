# 已支持能力与验证边界

| 能力 | 本包处理方式 |
|---|---|
| 独立项目初始化 | 数据工作区、课题 registry、四合同与模型模板 |
| CAD 审查 | 确定性 IR/DRC 与 WebGL 三维审查，保存可绑定版本 |
| 仿真 | 既有受支持适配器，经 Function/Guardian 建模、保存、求解、导出与重开 |
| 调参/优化 | 有界候选逐次走同一 cst_run 生命周期 |
| 查询、分析、对比 | cst_get 和已导出的 Touchstone；数值门与求解状态分别报告 |
| 批准 | 客户端真实 elicitation 或当前工作区明确授权；不随包附赠批准 |
| 知识 | 既有 Brain 检索、来源捕获、Function 学习与候选沉淀 |

首版实机执行平台为 Windows、Python 3.13；MCP SDK 保持 >=1.29,<2。当前完整的具体能力以实际适配器及新包验收报告为准。

以下**不因安装成功而自动获得支持**：任意已有 CST 工程编辑、任意原始 VBA、通用特征模/场图/远场导出、所有详细设置 getters，以及四支路同板 S8P。需求涉及这些能力时先检查适配器，开发并验证缺失部分再进入生产实验。

CLI/MCP 协议检查不是 Agent 客户端验收；单个低通实机闭环不是全部求解器覆盖；screen 不是最终高保真确认；缓存命中不是新求解。完整客户体验仍需要对应客户端实际加载与人工批准交互。

doctor 检查运行时来源、工作区合同与 Brain，并提供 CST 可执行文件/API 的发现结果；不会启动求解或替代实机验证。
